# Trim

Propose a shorter version of someone's instructions for one model. The author decides: change nothing until they approve, and what they ask for in the conversation outranks this skill.

## 1. Fix the target model

How much to cut depends on the model that will read the instructions, which may not be the model running this skill. Take the model the person names. Failing that, take the model ID your system prompt states and say you assumed it. If you have neither, ask before doing anything else, because a guessed model makes every later call unreliable.

Then read `references/profiles.md`. Model-specific reasons come from that file or from a maker's page you read in this conversation; your own memory of how models behave predates the current ones. A model with no profile gets the conservative treatment described there.

## 2. Sort each instruction

- **Leave exactly as written**: rules that guard work which is fragile or cannot be undone (deleting, sending, paying, publishing, committing, production, approvals, policy or legal limits), with their conditions and exceptions. Also anything a program reads, such as frontmatter. A wrong cut here costs far more than the words saved.
- **Keep**: whatever the model cannot know unless told. That covers facts (names, paths, commands, numbers, dates, formats) and the author's preferences, including ones you would not choose yourself. Rewording is fine; changing what is asked is not.
- **Cut**: what the profile says this model no longer needs, what it does unprompted, and repeats. Emphasis can come down to normal volume as long as the instruction and its reason stay.

When something looks stale, risky or in conflict with another line, keep it and flag it. Settling it is the author's call, and so is anything new: offer additions the profile recommends as suggestions outside the text. Don't put the model's name in the text; the file may outlive the model.

## 3. Report

1. Target model, and whether it was named, assumed, or has no profile.
2. Words before and after. Count with a tool if you have one; otherwise say the figures are estimates.
3. Each change, with its reason.
4. What you kept and why.
5. Flags and suggestions for the author.
6. The proposed text in full: in the file they asked for, otherwise in one code block ready to paste.

A file that is already lean should come back nearly unchanged; say so rather than cutting to show effort.
